# 白酒财报问答知识库

16 家 A 股白酒上市公司 × (2026 半年报 + 2025 年报) = 32 份财报全文，
做向量 + BM25 混合检索的问答系统，答案带出处（公司 / 报告 / 章节 / 页码 / 单位）。

数据来源：**巨潮资讯网**（cninfo.com.cn），财报全文 PDF。

---

## 跑起来

```bash
cd ~/projects/财报知识库

# 密钥只从环境变量读，绝不写进任何文件
export DASHSCOPE_API_KEY=sk-xxxx
export DASHSCOPE_BASE_URL=https://<你的工作区>.maas.aliyuncs.com/compatible-mode/v1

.venv/bin/python server.py     # 打开 http://127.0.0.1:8000
```

**必须用 `127.0.0.1` 而不是 `localhost`** —— 这台机器上 localhost 有时先解析到 `::1`，
而服务只监听 IPv4，浏览器报「拒绝连接」，但 `curl 127.0.0.1` 又是通的，很容易误判。

没设 key 也能跑：会退化成「只检索不生成」，把召回的原文和出处列出来。

**代理会让调用间歇性失败（2026-10-12 实测）。** 如果本机开着 Clash/Surge 这类代理，
`*.aliyuncs.com` 会被解析成 `198.18.0.x`（fake-ip 网段），直连全靠它的 TUN 隧道；
隧道一抖，`eval.py` 就在第一次 embedding 上调不动，报
`SSL: UNEXPECTED_EOF_WHILE_READING`。**这时候别去重新生成 key** ——
先 `curl -o /dev/null -w '%{http_code}' https://dashscope.aliyuncs.com`：
curl 通而 Python 不通，就是代理的问题（`net.py` 里显式清空了 proxy，不吃 `no_proxy`）。
换节点或临时关掉代理即可。
（对照：`api_test.py` 的端点探测走的是普通 `urlopen`，**会**吃系统代理，
所以它和 `eval.py` 的失败原因可能不是同一个。）

## 完整流水线

仓库里**不含**原始 PDF、向量和模型（共 2.3G），都要靠下面几步重新生成。

```bash
# 1. 下载 32 份财报（约 51M，走巨潮 API）
.venv/bin/python fetch.py

# 2. 解析 + 切块 → data/chunks.jsonl（正文按语义分块，表格按行列还原）
.venv/bin/python parse.py

# 3. 建索引 → data/vectors.npy + data/bm25.pkl（走 API 约 22 分钟）
.venv/bin/python index_build.py

# 4. 起服务
.venv/bin/python server.py
```

`data/manifest.json` 里记了每份 PDF 的 sha1，重下后可比对是否拿到同一批文件。

### 评测

```bash
.venv/bin/python eval.py              # 10 道题全跑（召回 + 生成）
.venv/bin/python eval.py 3 7          # 只跑第 3、7 题
.venv/bin/python eval.py --no-llm     # 只检索不生成
.venv/bin/python eval.py --report-only  # 按上次结果重写报告，不调大模型
```

产出 `data/eval_report.md`（人读，含逐题召回块清单 + 覆盖地图 + 回答 + 人工复核）
和 `data/eval_raw.json`（机器可读）。

判三个维度，互不替代：**召回**（块里有没有标准答案）、**回答**（模型答对没有）、
**覆盖**（全景题按公司取证时，该取到的公司是不是都取到了被问的字段 —— 单点题没有这一维）。

两个坑：**单跑某几题会覆盖 `eval_raw.json`**（只写本次跑的那些题），要补跑一题先备份；
`--report-only` 会按当前题库刷新题面描述（改措辞不必重跑大模型），但
**测量结果仍以 `eval_raw.json` 为准**。

### 全景取证的静态自检

全景取证的择优路径只走 BM25，不碰查询编码器，所以**没配 key 也能跑**：

```bash
.venv/bin/python retrieve.py --pano "这16家白酒公司里，2026年上半年营业收入同比实现正增长的有哪几家？"
.venv/bin/python retrieve.py --pano          # 不带问句就跑内置的三道
```

它逐家打印：取的是哪条路（锚点 / 回退）、取到哪个块哪一页、命中的项目与值、
期次和口径，以及 covered / partial / missing 的判定。改取证逻辑后先跑这个，
覆盖不完整会直接显示出来，不用花一次大模型调用。

| `make_doc.py` | 把评测结果导出成 Word（`白酒财报问答_10道评测题.docx`），并从 `结论.md` 重出 `结论.docx` |
| `web/index.html` | 问答页面（无密钥，密钥只在服务端） |
| `check_dup.py` | 表格重复块的健康检查 |
| `结论.md` | 一页结论：哪类题答得好、哪类翻车、为什么 |
| `结论.docx` | 同一份结论单独装订的 Word（**由 `make_doc.py` 生成，别手改**） |

## 几个不显然的设计决定

**为什么向量和 BM25 都要。** 向量对精确串和数字迟钝（问「600779 的营收」，它召回的是
「意思相近」的其他白酒公司，因为句子长得几乎一样）；BM25 对字面不重合的表达无效
（问「直接销售取得的收入」，原文写的是「直销渠道收入」）。两条腿缺一不可。

**RRF 而不是加权求和。** 余弦相似度 0.7 和 BM25 得分 12.3 量纲不可比，硬加权才是错的。
RRF 只看排名：`score(d) = Σ 1/(K + rank_i(d))`，K=60。

**同公司配额 `MAX_PER_COMPANY=3`。** 一份 116 页年报能产出 500 多个块，16 家竞争 top-6 时
很容易 6 个块全来自同一家，「对比各家」类的问题就废了。

**全景题走旁路通道，并且按公司取证。** 纯 top-k 架构上答不了「16 家谁净利润最高」——
它最多召回 6 个块，覆盖不到 16 家公司。所以按公司身份把各家该问的那个字段捞出来，
**并且校验字段到底在不在**：锚点块坏了就回退到该公司别的块，回退也取不到就如实标
「缺据」并写进覆盖地图，让模型点名说明。只取锚点不校验的代价见 `结论.md`：
**锚点坏一家，那一家就整个消失且不报警。**

**覆盖地图摆的是「被问的那一列」，不是字段的绝对值。** 问「哪几家同比正增长」，
能据以判断的是**同比**那一列；只摆营业收入绝对值，模型就得自己回 16 张原文表里翻
同比 —— 2026-10-12 实测它就是这么把全场增速最高的五粮液（+20.87%）漏掉的，还写下
「其余 13 家同比均为负增长」。所以地图每行同时给「值 + 同比」，**按同比降序排**（正号
挤成一段前缀），并在末尾给一行**方向小计**（正几负几）当对账数。注意这一行只说
"有几家"，不说"是哪几家" —— 名单仍由模型按公司名列出，**系统只负责把账核齐**。
问「净利润为负」那类题不加小计：那一列本身带正负号，摆在值列里一眼就能看出来。

**查询编码器必须和建索引时一致。** 本地 Qwen3 和百炼 text-embedding-v4 是两个不同的
向量空间，拿 A 的查询向量点乘 B 的索引向量**不抛异常**，只是结果错得看不出来。
所以后端名从 `index_meta.json` 读，不靠环境变量猜；取不到就报错，不静默退回本地。

**密钥只从环境变量读。** 不写进文件、不下发到浏览器 —— 这条没有例外。
`web/index.html` 里没有任何密钥，浏览器只能调本机的 `/api/ask`。
